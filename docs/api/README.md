# API документация DED_CORE_V4

## Обзор API

DED_CORE_V4 предоставляет RESTful HTTP API и WebSocket интерфейс для управления системой зажигания и мониторинга параметров в реальном времени.

## Базовый URL

| Интерфейс | Адрес | Что там |
|---|---|---|
| HTTP | `http://192.168.4.1/` | вшитый веб-интерфейс (из LittleFS), страница `/update`, API устройства |
| WebSocket | `ws://192.168.4.1:81/` | телеметрия и команды (см. ниже) |
| HTTPS | `https://core.dedbox.pro/` | тот же фронт по TLS; имя резолвит AP-DNS блока, сертификат в LittleFS |
| WSS | `wss://core.dedbox.pro/ws` | телеметрия для HTTPS-приложения |
| HTTPS | `/api/status`, `/api/tls`, `/api/ai/grant`, `/api/migration`, `/api/migrate` | служебные эндпоинты блока |

Порт 443 нужен потому, что браузер запрещает `ws://` и `http://` со страницы HTTPS:
приложение открывается по HTTPS и общается с блоком по WSS.

## Аутентификация

Пароль точки доступа — **не** учётные данные: он нужен, чтобы подключиться к сети блока,
и его знает любой, кто к ней подключился. Поэтому аутентификация построена на ключе
устройства (`X-Device-Key`, выдаётся приложением при привязке):

- чтение состояния (`/status`, `/device/config`, `/card`, `/max`, …) — из сети блока;
- **смена состояния** (`/wifi`, `/wifi/updator`, `/wifi/auto`, `/wifi/connect`, `/flash`,
  `/ota/update`, `/ota/mode`, `/ota/password`, `/core/reboot`) — по ключу устройства; пока
  ключ не выдан (блок не привязан), изменения разрешены из сети блока, чтобы первичная
  настройка оставалась возможной;
- `GET /wifi/pass` (пароль точки доступа) — только по ключу устройства;
- `/update` и `POST /api/update` — по ключу устройства; из сети блока — только пока ключ
  не выдан. Образ дополнительно сверяется по `md5`, если параметр передан;
- `/api/status` — из сети блока, но код сопряжения в ответе появляется только по ключу;
- `/api/tls`, `/api/tls/refresh`, `/api/ai/grant` — по ключу устройства (из сети блока —
  только до провижининга);
- `/api/provision` — приём ключа устройства при провижининге;
- `/api/migration`, `/api/migrate` — переход на новую разметку: команду отдаёт сервис,
  адрес образа берётся из его ответа.

Пароль точки доступа уникален для блока: он генерируется случайным при первом включении
и хранится в NVS. В прошивке его нет — иначе он был бы известен из публичного репозитория.

## Форматы данных

### HTTP запросы
- **Метод**: GET/POST
- **Параметры**: query string
- **Ответ**: plain text или JSON

### WebSocket сообщения
- **Формат**: JSON
- **Кодировка**: UTF-8
- **Направление**: двунаправленный обмен

## HTTP эндпоинты

### Системные эндпоинты

#### Получение версии прошивки
```http
GET /core/version
```
**Ответ**: `4.0.16`

#### Перезагрузка системы
```http
GET /reinit
```
**Ответ**: `FIRMWARE_VERSION`

### Управление картами зажигания

#### Выбор активной карты
```http
GET /card?id={1|2|3}
```
**Параметры**:
- `id` - номер карты (1-3)

**Ответ**: `OK`

#### Обновление точки карты
```http
GET /update_card?id={0-21}&rpm={value}&angle={value}&angle_adv={value}&quick_adv={value}&servo={value}
```
**Параметры**:
- `id` - индекс точки (0-21)
- `rpm` - обороты
- `angle` - угол зажигания
- `angle_adv` - коррекция по дросселю
- `quick_adv` - настройка быстрого переключения
- `servo` - значение сервопривода

**Ответ**: `OK`

### Настройка отсечек

#### Настройка максимальных оборотов
```http
GET /max?rpm={value}&angle={value}
```
**Параметры**:
- `rpm` - максимальные обороты
- `angle` - коррекция угла при отсечке

**Ответ**: `OK`

### Управление углом зажигания

#### Включение коррекции по дросселю
```http

```
**Параметры**:
- `status` - 0 (выкл) или 1 (вкл)

**Ответ**: `OK`

#### Настройка начального угла
```http
GET /angle?init={value}
```
**Параметры**:
- `init` - начальный угол в градусах

**Ответ**: `OK`

### Тип карты зажигания

#### Установка типа карты

```http
GET /type?set={0|1|2}&new_chart_type={1-6}
```
**Параметры**:
- `set` - тип карты (0=7 точек, 1=12 точек, 2=22 точки)

### Получение команд от клиента

#### Переключение карты
```json
{
  "event": "cart",
  "data": {
    "cart": 2
  }
}
```

#### Пинг-понг
```json
{
  "event": "ping"
}
```

#### Чтение точки карты зажигания

```json
{
  "event": "map_point",
  "data": {
    "cart": 1,
    "point": 5
  }
}
```

Ответ — та же точка со значениями (углы в градусах, `qa` — коррекция квикшифтера,
`servo` — значение сервопривода):

```json
{
  "event": "map_point",
  "data": {
    "cart": 1,
    "point": 5,
    "rpm": 4000,
    "angle": 29,
    "aa": 1,
    "qa": 0,
    "servo": 105
  }
}
```

Если индекс вне таблицы (`cart` не 1…3 или `point` не 0…21), приходит
`{"event":"map_point","data":{"error":"bad index"}}`.

#### Запись точки карты зажигания

Точка пишется в таблицу зажигания и в энергонезависимую память (так же, как маршрут
`GET /update_card` на порту 80), поэтому блок помнит её после перезагрузки. Значения,
которых нет в кадре, остаются прежними.

```json
{
  "event": "map_set",
  "data": {
    "cart": 1,
    "point": 5,
    "rpm": 4000,
    "angle": 29.5,
    "aa": 1,
    "qa": 0,
    "servo": 105
  }
}
```

Ответ:

```json
{
  "event": "map_set",
  "data": {
    "cart": 1,
    "point": 5,
    "saved": 1
  }
}
```

Таблицу приложение обходит по одной точке: кадр канала ограничен уведомлением
Bluetooth, и вся карта (до 22 точек × 5 значений) в него не помещается.

#### Ошибка сервопривода
```json
{
  "event": "servo_error"
}
```

## Примеры использования

### JavaScript - выбор карты
```javascript
fetch('http://192.168.4.1/card?id=2')
  .then(response => response.text())
  .then(data => console.log(data));
```

### JavaScript - обновление точки карты
```javascript
const params = new URLSearchParams({
  id: 5,
  rpm: 4000,
  angle: 32.5,
  angle_adv: 0.2,
  quick_adv: 135,
  servo: 10
});

fetch(`http://192.168.4.1/update_card?${params}`)
  .then(response => response.text())
  .then(data => console.log(data));
```

### WebSocket - подключение
```javascript
const ws = new WebSocket('ws://192.168.4.1:81/');

ws.onmessage = function(event) {
  const data = JSON.parse(event.data);
  console.log('RPM:', data.data.rpm);
  console.log('Угол:', data.data.advance_angle);
};

// Переключение карты
ws.send(JSON.stringify({
  event: 'cart',
  data: { cart: 3 }
}));
```

### Python - запрос версии
```python
import requests

response = requests.get('http://192.168.4.1/core/version')
print(f'Версия прошивки: {response.text}')
```

### Python - мониторинг через WebSocket
```python
import websocket
import json

def on_message(ws, message):
    data = json.loads(message)
    print(f"RPM: {data['data']['rpm']}")
    print(f"Угол зажигания: {data['data']['advance_angle']}")

ws = websocket.WebSocketApp("ws://192.168.4.1:81/", on_message=on_message)
ws.run_forever()
```

## Служебные эндпоинты блока

Эти маршруты появились позже остальных и нужны приложению и сервису, а не человеку с браузером.

| Метод | Назначение | Права |
|---|---|---|
| `GET /api/status` | Состояние блока: MAC, версия, слот, режим; код сопряжения — только по ключу | сеть блока или `X-Device-Key` |
| `POST /api/tls` | Приём пары сертификат/ключ (JSON) | `X-Device-Key` |
| `GET /api/tls/refresh` | Запросить новый сертификат у сервиса по HTTPS | `X-Device-Key` |
| `POST /api/ai/grant` | Подпись nonce для чата «Люси»: `{nonce}` → `{mac, signature}` | `X-Device-Key` |
| `POST /api/provision` | Провижининг: ключ устройства и параметры | по проводу или `X-Device-Key` |
| `GET /api/migration` | Нужен ли переход на новую разметку и параметры образа | — |
| `POST /api/migrate` | Подтверждение перехода (адрес образа берётся из ответа сервиса) | — |
| `GET /update` | Страница загрузки образа в блок (ElegantOTA-подобная) | — |
| `POST /api/update` | Приём образа прошивки (`app` / `fs`), необязательный `md5` | `X-Device-Key` |
| `POST /module/pair/start` | Открыть окно сопряжения модуля на 90 секунд | ключ устройства или сеть блока |
| `POST /module/pair/stop` | Закрыть окно сопряжения досрочно | ключ устройства или сеть блока |
| `GET /module/pair` | Параметры точки доступа для внешнего модуля | только сеть сопряжения и открытое окно |

### Сопряжение внешних модулей

Модули (сервопривод, датчики и прочее) подключаются к точке доступа блока, но её
пароль уникален для каждого блока и не отдаётся ни по HTTP без `X-Device-Key`, ни
в кадре телеметрии. Поэтому блок на 90 секунд поднимает открытую сеть
`DED_PAIR_<4 hex>` (хвост MAC) вместо основной точки доступа.

Кнопок на блоке нет, поэтому окно открывает владелец из приложения:

```
POST /module/pair/start
X-Device-Key: <ключ устройства>
```

Ответ:

```json
{
  "event": "module_pair",
  "data": {
    "active": 1,
    "ssid": "DED_PAIR_1A2B",
    "window_ms": 90000
  }
}
```

Через 700 мс после ответа основная точка доступа подменяется сетью сопряжения,
поэтому телефон отключается от блока до конца окна. `POST /module/pair/stop`
закрывает окно досрочно.

`GET /module/pair` из этой сети отдаёт:

```json
{
  "event": "module_pair",
  "data": {
    "ssid": "DED_BOX_V4",
    "pass": "уникальный пароль блока",
    "host": "192.168.4.1",
    "port": 81,
    "token": "<токен модуля>",
    "fw": "4.0.16"
  }
}
```

`token` — пропуск доверенного модуля. По нему блок отличает сопряжённый модуль
от телефона или чужого клиента в своей сети и только таким клиентам присылает
новые параметры точки доступа (см. «Доверенные модули»).

Ответ приходит только при открытом окне и только из подсети `192.168.4.0/24`;
иначе — `403`. Через 3 секунды после ответа основная точка доступа возвращается
(ESP32 держит одну точку доступа, поэтому на время окна телефон владельца
отключается от сети блока). Реализация — `core/net/MODULE_PAIRING.h`.

### Доверенные модули

Сопряжённый модуль подтверждает токен при каждом подключении:

```json
{
  "event": "module_hello",
  "data": {
    "mac": "AA:BB:CC:DD:EE:FF",
    "fw": "1.0.0",
    "token": "<токен модуля>"
  }
}
```

Ответ — `{"event":"module_hello","data":{"trusted":1}}`; при неизвестном токене
`trusted` равно 0 и модуль считается обычным клиентом.

Когда владелец меняет имя или пароль точки доступа (`GET /wifi` или команда
`{"event":"ap"}`), блок сначала рассылает новые параметры доверенным модулям:

```json
{
  "event": "module_credentials",
  "data": {
    "ssid": "DED_BOX_V4",
    "pass": "новый пароль",
    "host": "192.168.4.1",
    "port": 81
  }
}
```

и только через 1,5 секунды перезапускает точку доступа. Модуль сохраняет
параметры и переподключается сам — связка не теряется. Токены хранятся в NVS
(до восьми штук): пересопряжение одного модуля не отзывает токены остальных.

Проверка обновления устройством идёт не с блока, а **от блока к сервису**:
`GET /device/check?current=&type=&slot=` и `GET /device/download` с заголовком
`X-Device-Key` на стороне сервиса (`dedbox.pro`), поэтому в таблицах выше они не описаны.

## Обновление прошивки

- `GET /ota/check` — блок сам проверяет релиз на сервисе и отдаёт результат;
- `GET /ota/status` — состояние: режим, подключение к сети обновления, наличие новой версии;
- `POST /ota/update` — запустить загрузку и установку;
- `POST /ota/mode?mode=0|1|2` — режим OTA: 0 AUTO, 1 MANUAL, 2 OFF;
- `POST /ota/password?password=` — пароль локального обновления (ArduinoOTA; в текущей
  сборке этот путь выключен флагом `DED_CORE_NO_ARDUINO_OTA`).

## Ошибки

### HTTP коды ответа
- **200** - Успешное выполнение
- **404** - Эндпоинт не найден
- **500** - Внутренняя ошибка сервера

### WebSocket ошибки
- **Отключение** - потеря соединения
- **Неверный JSON** - ошибка парсинга
- **Событие не найдено** - неизвестный тип события

## Ограничения

### Частота запросов
- **HTTP**: не более 10 запросов в секунду
- **WebSocket**: не более 50 сообщений в секунду

### Размер данных
- **HTTP**: максимальная длина URL 2048 символов
- **WebSocket**: максимальный размер сообщения 5KB

### Диапазоны значений
- **RPM**: 0-12000 об/мин
- **Угол зажигания**: 0-90 градусов
- **Дроссель**: 0-100%
- **Карта**: 1-3
