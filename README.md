# DED_CORE_V4 - Универсальная система управления зажиганием

[![PlatformIO](https://img.shields.io/badge/PlatformIO-ESP32-blue.svg)](https://platformio.org/)
[![License](https://img.shields.io/badge/License-NonCommercial-orange.svg)](LICENSE)
[![Version](https://img.shields.io/badge/Version-4.0.16-red.svg)](src/config/PROPS.h)

**DED_CORE_V4** - это программируемый блок управления зажиганием (ECU) на базе ESP32 с универсальной поддержкой различных типов двигателей и веб-интерфейсом для настройки.

## 🚀 Основные возможности

- **Универсальная поддержка двигателей** - настраиваемые карты зажигания для любого ДВС
- **3 независимые карты** - быстрое переключение между режимами
- **Веб-интерфейс** - удобная настройка через браузер
- **Отсечка** - порог по активной карте (`max_rpm`) и снятие угла на нём (`max_rpm_angle_kiker`)
- **Real-time мониторинг** - отслеживание параметров в реальном времени
- **WiFi подключение** - беспроводная конфигурация
- **Обновление по воздуху** - OTA обновления прошивки
- **Люси на странице блока** - чат с ИИ по телеметрии; включается, когда у блока есть
  домашняя сеть и он привязан к учётной записи (см. `docs/api/README.md`, `/api/ai/grant`)

🌐 Серверная инфраструктура
Этот проект является клиентской (прошивка) частью экосистемы DED MOTO SYSTEM.

Центральный сервер: dedbox.pro

Статус: Серверная часть работает на закрытом исходном коде и обеспечивает синхронизацию данных, аналитику и управление настройками в реальном времени.

## 🛠️ Быстрый старт

### Требования
- ESP32 Dev Board
- Датчик положения коленвала
- Датчик дроссельной заслонки
- Катушка зажигания

### Установка
1. Клонировать репозиторий
2. Открыть в PlatformIO
3. Скомпилировать и прошить
4. Подключиться к WiFi точке `DED_BOX_V4` — пароль **уникален для каждого блока**
   (генерируется при первом включении, в прошивке его нет). Узнать его можно в логе
   первого включения (`AP password generated: …`) или в приложении по Bluetooth после
   нажатия кнопки «карта вниз»; по HTTP его отдаёт `GET /wifi/pass` с заголовком
   `X-Device-Key`
5. Открыть браузер по адресу `192.168.4.1`

### Первая настройка
1. Выберите тип карты (7/12/22 точки)
2. Настройте базовые параметры зажигания
3. Сохраните конфигурацию
4. Проверьте работу двигателя

## ⚙️ Конфигурация

### Типы карт зажигания
- **Type 0** - 7 точек (базовая настройка)
- **Type 1** - 12 точек (средняя точность)
- **Type 2** - 22 точки (максимальная точность)

### Отсечка
Порогов два, и они не «по картам»: `max_rpm` (общий, задаётся `/max`) и седьмая точка
RPM активной карты (`rpmsArr[active_cart][6]`). На отсечке угол уменьшается на
`max_rpm_angle_kiker`. См. `src/core/handlers/Alarm.h`.

## 🔧 Разработка и компиляция

### 🖥️ Встроенный интерфейс

Исходники страницы блока лежат в `web/` (Angular, без внешних UI-библиотек и тяжёлых
графиков). Сборка раскладывает готовый бандл в `data/`, откуда PlatformIO собирает образ
LittleFS:

```bash
cd web
./build.sh          # ставит зависимости при первом запуске и заменяет ../data
cd ..
./flash-device.sh -p /dev/cu.usbserial-0001 --fs-only
```

Собранный интерфейс занимает ~290 КБ из 1088 КБ раздела — запас остаётся под сертификат
`/cert.pem`, `/key.pem` и будущие страницы. Старый Angular-бандл (~930 КБ) больше не
используется.

- **PlatformIO**: Среда разработки
- **ESP32 Arduino Framework**: Фреймворк
- **C++17**: Стандарт языка
- **Git**: Система контроля версий

## 🔐 Безопасность и обслуживание

Модель безопасности рассчитана на то, что исходники публичны: в прошивке нет ни одного
пароля, который нельзя было бы заменить, и границей безопасности не считается пароль
точки доступа.

**Сеть блока**

- Точка доступа `DED_BOX_V4` защищена паролем, который **уникален для каждого блока**: он
  генерируется при первом включении и хранится в NVS, в прошивке его нет.
- Узнать пароль: в логе первого включения (`AP password generated: …`), в приложении по
  Bluetooth (команда `pair_info`) или по HTTP `GET /wifi/pass` с ключом устройства.
- Аварийный режим `DED_RECOVERY` включается удержанием кнопки «карта вниз» при подаче
  питания, использует тот же пароль блока, пароль печатается в лог. Веб-панель
  восстановления, перепрошивка и сброс настроек доступны только в этом режиме.

**API (порты 80 / 81 / 443)**

- Смена состояния (`/wifi`, `/wifi/updator`, `/wifi/auto`, `/wifi/connect`, `/flash`,
  `/ota/update`, `/ota/mode`, `/ota/password`, `/core/reboot`) требует ключ устройства в
  заголовке `X-Device-Key`. Пока ключ не выдан (блок не привязан), изменения разрешены
  только из сети блока — иначе первичная настройка была бы невозможна.
- `GET /wifi/pass` — только по ключу устройства; `wpass` в телеметрии WebSocket не
  передаётся.
- `POST /api/update` — по ключу; из сети блока только до привязки. Контрольная сумма
  проверяется до `Update.end()`, для локальной заливки можно передать `md5`.
- `/api/status` отдаёт код сопряжения только по ключу. Статика **не отдаёт** `/key.pem`
  и `/cert.pem`.
- Ключ устройства принимается длиной 32…128 символов, сравнение — в постоянном времени.

**Bluetooth**

- Провижининг ключа (`provision`) и выдача MAC / кода / пароля точки доступа
  (`pair_info`) работают только в течение 60 секунд после нажатия кнопки на самом блоке.
  BLE-стек поднят без бондинга намеренно: Just Works подделывается, поэтому аутентичность
  даёт подтверждение физическим действием и подпись сервиса, а не спаривание.

**Карта зажигания**

- Значения `map_set` (RPM, угол, коррекции, серво) подрезаются теми же пределами, что и
  поля встроенной страницы: команда из радиуса не может выставить угол за границы,
  допустимые для двигателя.

**Обновления**

- **OTA с сервера** — блок сам проверяет релиз по ключу устройства (`/device/check`,
  `/device/download`) и ставит его в свободный слот; адрес скачивания приводится к
  собственному HTTPS-хосту, сертификат сервера проверяется по корням Let's Encrypt.
- **Обновление с компьютера** — страница `/update`, `POST /api/update` (см. права выше).
- **Проверка версии по запросу** — `/ota/check`, состояние — `/ota/status`.
- Автоматического резервного копирования настроек и отката прошивки в коде нет: два
  app-слота позволяют откатиться только вручную, прошив прежний образ.
- ArduinoOTA по UDP в текущей сборке выключен (`DED_CORE_NO_ARDUINO_OTA`); если его
  включить, он не поднимется без пароля длиной 8+ символов.

**Что остаётся за рамками прошивки** — подпись образа и Secure Boot v2, flash encryption
для ключа устройства и пароля Wi-Fi, ротация ключей. Чек-лист перед серией:
[`docs/technical/production-security.md`](docs/technical/production-security.md).

## 🔐 Провижининг и управление (DED CORE CONTROL)

Устройство, прошитое нашим сервисом, получает обновления по **ключу устройства** и
управляется из приложения (раздел DED CORE CONTROL) по WiFi или Bluetooth.

- **Ключ устройства.** Хранится в NVS (`ded_box` / `device_key`), передаётся серверу в
  заголовке `X-Device-Key` при проверке (`/device/check`) и скачивании (`/device/download`)
  обновления. Выдаётся при провижининге; мастера присылают его по проводу командой
  `{"event":"provision","data":{"key":"…"}}`.
- **WiFi.** Веб-сервер с WebSocket (`ws://192.168.4.1:81`) отдаёт телеметрию
  `{"event":"message","data":{...}}` и принимает команды `ping`/`cart`. Это тот же канал,
  что использует вшитый веб-интерфейс.
- **HTTPS/WSS.** Порт 443 отдаёт `https://core.dedbox.pro/` (вшитый фронт) и
  `wss://core.dedbox.pro/ws` — нужен, чтобы HTTPS-приложение могло связаться с блоком
  (браузер запрещает `ws://` из HTTPS). Имя резолвит AP-DNS самого блока. Сертификат
  кладётся в SPIFFS (`/cert.pem`, `/key.pem`) по проводу или по `POST /api/tls`
  с заголовком `X-Device-Key`.
- **Bluetooth.** GATT-сервис на NimBLE (UUID — см. `src/core/ble/BLE_SERVER.h`): notify
  телеметрии и write команд. Не зависит ни от DNS, ни от сертификата.

Файлы: `src/core/ota/OTA_MANAGER.*`, `src/core/provision/PROVISION.h`,
`src/core/ble/BLE_SERVER.h`, `src/core/net/TLS_SERVER.{h,cpp}`, `partitions_ded_core.csv`.

> Флеш-разметка расширена (`partitions_ded_core.csv`): дефолтной партиции под приложение
> больше не хватает. Устройства прошиваются по проводу (`pio run -t upload`), фронт —
> `pio run -t uploadfs`. Подробности и выпуск сертификата — в
> `docs/ded-core-tls.md` — документ живёт в основном репозитории платформы
> DED MOTO SYSTEM и в этом репозитории прошивки отсутствует.
